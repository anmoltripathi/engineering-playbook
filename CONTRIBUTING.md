# 🤝 Contributing Guide

Thank you for your interest in contributing to the **Frontend Engineering Playbook (FEP)**.

Our goal is to build one of the most practical and high-quality open-source resources for Frontend and Full Stack Engineers.

---

# Before You Contribute

Please ensure that your contribution:

* Is technically accurate.
* Includes practical examples where appropriate.
* Follows the repository structure.
* Uses clear and concise language.
* Avoids duplicate content.
* Has been reviewed for grammar and formatting.

---

# Types of Contributions

We welcome:

* Documentation improvements
* Bug fixes
* New technical articles
* Code examples
* Architecture diagrams
* Cheat sheets
* Performance tips
* Production case studies

---

# Branch Naming

Use descriptive branch names.

Examples:

* feature/react-virtual-dom
* feature/javascript-closures
* docs/readme-update
* fix/typo-authentication

---

# Commit Message Convention

Use conventional commits.

Examples:

* feat: add React Virtual DOM guide
* docs: improve README
* fix: correct JWT example
* refactor: simplify code example

---

# Pull Request Checklist

Before opening a Pull Request:

* Code or documentation has been reviewed.
* Markdown formatting is correct.
* Internal links work.
* Examples are tested (if applicable).
* No unnecessary files are included.

---

# Documentation Standard

Every technical article should include:

1. Overview
2. Why It Matters
3. Core Concepts
4. Code Example
5. Real-world Use Case
6. Common Mistakes
7. Best Practices
8. Interview Questions
9. References

---

# Community

Please be respectful and constructive in discussions.

Let's build something valuable for the engineering community.
