# Frontend Engineering Playbook Style Guide

> **Version:** 1.0
>
> This guide defines the writing, formatting, and documentation standards for the Frontend Engineering Playbook.
>
> Every document, article, tutorial, cheatsheet, and project documentation must follow these standards.

---

# Purpose

This guide ensures that every piece of content is:

- Consistent
- Easy to read
- Technically accurate
- Beginner friendly
- Senior engineer approved
- Easy to maintain

---

# Writing Principles

Always explain:

**Why → What → How → When**

Never explain only "how".

Readers should understand:

- Why the concept exists
- What problem it solves
- How it works
- When it should be used
- When it should NOT be used

---

# Writing Tone

The repository should sound like:

- Senior Software Engineer
- Technical Mentor
- Professional Documentation

Avoid:

❌ Marketing language

❌ Clickbait

❌ "Amazing"

❌ "Super easy"

❌ "Magic"

❌ "Just"

❌ "Simply"

Use:

✅ Clear

✅ Professional

✅ Practical

✅ Engineering-focused

---

# Markdown Standards

## Headings

Use only one H1.

```md
# Title

## Major Section

### Subsection

#### Topic
```

Do not skip heading levels.

---

## Lists

Prefer unordered lists.

```md
- HTML
- CSS
- JavaScript
```

Numbered lists only when order matters.

---

## Tables

Use tables for:

- Comparisons
- Browser support
- Interview summaries
- Feature matrices

---
